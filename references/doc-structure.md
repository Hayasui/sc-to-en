# 用研 md 文档结构规范

这份文档定义"什么样的 md 结构，既方便人和 AI 修改、又能逐条复制到 UserTesting"。

## 整体结构

一份用研 md 通常包含三层：

```
┌─ 头部元信息（项目/方式/时长/样本/语言）
├─ 平台配置说明（内部参考，不上线）
│   ├─ 整体任务流
│   ├─ 题型与平台对应关系
│   ├─ 关键设计原则
│   └─ 语言要求
├─ 任务结构总览表（内部参考，可照此配置）
├─ 逐题配置清单（玩家可见 ← 重点，可直接粘贴）
│   ├─ Task A · Instruction
│   ├─ Task A · Navigation
│   └─ Task B · Page 1..N（每页若干题）
├─ 内部研究参考（研究问题 RQ、分析维度，不上线）
└─ 主持人/分析者提醒（内部参考）
```

**关键**：玩家可见部分和内部参考部分**物理上分开**，用明显的标题区隔。这样本地化时能一眼看出"哪些该改、哪些不该动"。

## Task 拆分

UserTesting 上通常是 **2 个 Task**：

| Task | 内容 | 说明 |
|------|------|------|
| **Task A** | Instruction（开场说明）+ Navigation（下载并打开游戏） | 纯说明，无题目 |
| **Task B** | 试玩后的完整问答 | 含多个 Question Page |

**为什么 Instruction 和 Navigation 要分开**：两者都有 1000 字符限制，分开后各司其职（见 `platform-constraints.md` 第 1 节）。

## 每道题的字段格式

每道题用统一的字段块，便于扫描和粘贴：

```markdown
#### Q5　`[Multiple Choice · single · required]`　Research focus: Set baseline (formerly 4.2)

**题干**：你刚才玩了今天这款游戏……你觉得**下面哪一款和今天这款最像**？……**请你记住自己选的这一款——后面几道题我们还会再提到它。**

- Travel Town – Merge Adventure
- Merge Mansion
- ...
- 其他

> **内部备注**：此题为后面所有对照题的锚点……
```

**题号写法**：同一项目内**中英两侧用同一套题号写法**，读的人不会对不上号。
`3D二合` 项目自 2026-09-11 起中英两侧统一用 **`Q N`**（跟着内容基准表格 V4 走，
不再用 `问题 N`）。lint 脚本的题号正则兼容 `Q` / `题` / `问题` 三种写法，换写法不报警。

> **占号但不是问答题的单元**：无人版里「Task A · Navigation（下载并打开游戏）」占 Q1，
> 它写在标题里（``### Task A · Navigation　`Q1` ``）而不是 `#### Q1` 标题行；
> 有人版则没有 Q1 对应题。lint 的交叉引用检查认这种写法，不会把正文里的 Q1 引用报成悬空。

字段说明：

| 字段 | 内容 | 是否上线 |
|------|------|---------|
| `#### Q N` | 题号（内部沟通用，上线删除） | 否 |
| `` `[题型 · 单选/多选 · 必答/选答]` `` | 平台配置用的题型与必答标记 | 是（题型） |
| `研究落点：...` | 这题服务于哪个研究问题 | 否 |
| `**题干**` | 玩家看到的题目 | 是 |
| 选项列表 | 玩家看到的选项 | 是 |
| `**量表标签**` | 量表题的 Scale Labels（仅量表题） | 是 |
| `> **内部备注**` | 给研究团队的说明 | 否 |

### 内嵌追问属于题干，不另立字段（2026-09-11）

想提醒玩家"边填定量题、边开口补充"的那些追问（「选完之后，顺便说说……」），
**是题干的一部分，不是独立字段**。它们的去向是平台上的**题干输入框**，而那个框支持换行。

所以文档里的排法是：**紧接题干文字的下方另起行写，不带任何字段名**——
玩家不该看到「内嵌追问（文字分支，按自己的情况认领一段）：」这类标签，那是给内部看的。

```markdown
**题干**：过去 1 个月里，你在二合游戏上大概花了多少钱（比如买金币、道具、通行证之类）？

如果你刚才选的是"没花过钱"——是什么让你没花钱？……

如果你花过钱——具体买的是哪个游戏的哪些内容？……

- 没花过钱
- $1-9
```

三条要点：追问行**不要加 `- ` 前缀**（选项也是 `- `，加了分不清哪些是选项，配置时容易一起框进去）；
**分支题不加额外的引导句**——不要写"下面两段，选跟你情况相符的一段说就行"这类话，
`如果你刚才选的是… / 如果你花过钱…` 这样的条件开头本身已经说明该认领哪段，
多加一句会让中英在"玩家可见内容"上分叉（英文补一句就多出一段玩家可见文字）；
量表题里追问紧接题干，**Scale Labels 作为配置项排在题干块之后**。
（三条均由用户于 2026-09-11 裁决定案。）

> 有人版的「追问方向」是主持人现场用的，**不进玩家可见题干**，保持独立分栏，
> 不要跟这条混起来。

## 页面引导语

每个 Question Page 开头可以有一句引导语，帮玩家进入状态：

```markdown
> **页面引导语**：接下来请你给刚才的体验打打分、谈谈感受。答案没有对错，凭第一印象就好。
```

引导语是**玩家可见**的，需要本地化。

## 量标题的写法

量表题必须显式写出 Scale Labels：

```markdown
**量表标签**：**1 = 非常不满意** 　|　 **10 = 非常满意**
```

英文版的端点措辞**照 `survey-wording.md` 取**（唯一出处），不要在本文档里写死某一套。

Matrix 题同时给行（陈述）和列（量表）结构：

```markdown
| 陈述 | 1 很不同意 | 2 | 3 | 4 | 5 很同意 |
|------|:--:|:--:|:--:|:--:|:--:|
| 我一上手就能理解这个棋盘怎么玩 | ☐ | ☐ | ☐ | ☐ | ☐ |
```

## 新建文档时的骨架

用户要新建用研 md 时，**只给骨架，不代写研究内容**：

1. 头部元信息（留空待填：项目、测试方式、时长、样本画像、核心验证对象）
2. 平台配置说明（照抄规范，项目相关处留空）
3. 任务结构总览表（列出 Task A / Task B 的框架，题目内容留空）
4. 逐题配置清单（给出 Task A Instruction / Navigation 的模板，Task B 各 Page 的框架）
5. 内部研究参考（列出 RQ 的框架：假设、一句话落点、看什么、关键分辨）
6. 主持人提醒（照抄通用提醒）

**不要**替用户写具体的题目内容、选项、研究假设——那是用户的专业判断。骨架只保证"结构对、字段全、能直接往平台贴"。

## 中英双版本的文件组织

```
xxx.md          中文定稿（源头，内部审阅 + 与需求方沟通）
xxx_EN.md       英文本地化版（可直接配置到 UserTesting）
```

两份文件**平行存在**，不是替代关系。中文版是定稿源头，英文版是本地化产物。

**同步规则**：英文版措辞可单边调整；语义改动必须回写中文版。

### 有人版 / 无人版并存时的命名

```
3D二合北美无人访谈大纲.md       + _EN.md
3D二合北美有人访谈大纲.md       + _EN.md
```

命名格式：`{项目简称}有人/无人访谈大纲`，英文加 `_EN` 后缀。

**两版的关系**：**题号与研究落点一一对应**，但承载形式按访谈场景各自调整——差别不只是
"追问由谁发起"，题型本身也可能不同。2026-09-14 在 `3D二合` 上定下的三处偏离
（无人版照平台能力办，有人版照真人对话办）：

| 题 | 无人版（照平台） | 有人版（照对话） |
|---|---|---|
| Q2、Q8 | Multiple Choice，念清单让玩家认领 | 开放式提问，玩家自发举例；清单退成主持人的**记录清单**，只记不念 |
| Q19 | Matrix（1-5，七条陈述） | 三问定性，不给分数；两版数据分开看 |
| Q33 | Ranking，按固定清单排序 | 先让玩家自发列举问题，再排序；清单只作主持人补足用 |

对照两版时，别把这种偏离当成"有人版漏配了题"。

从无人版转有人版时，除了题型差异，还要把：

- 题干里的"顺便说说……"邀请句 → 主持人的**现场追问**
- 独立 Verbal response 题 → 主持人的**主题提问**
- 文字分支的两段 → 主持人按实际情况**选问一支**
- "请玩家自己记住基准游戏" → **主持人记下并每次复述**

**有人版的专属结构**（无人版没有的）：

- 「访谈执行说明」：时间分配表、主持人纪律、记录方式
- 每题三栏：**提问话术**（可直接念）+ **追问方向**（含"加深层"）+ **观察记录点**
- 主持人在试玩环节的角色说明

**若测试含尖叫度配对打分**：试玩环节必须**静默观察**，主持人不得追问，
否则污染玩家对游戏的初始判断，满意度差值失效。这条要写进主持人纪律的第一条。
